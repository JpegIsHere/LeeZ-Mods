# Cause found

The previous chat inspected the V3.1 `BlockPoweredLight.updateLightState` IL.

Vanilla only automatically switches lights under direct children named:

`MainLight`

or:

`Point light`

and those branches need a `LightLOD`.

The custom Test6 T1 Unity `Light` is outside that vanilla-managed hierarchy.

Therefore our colour/brightness runtime was finding and modifying the custom Unity `Light`, but vanilla was never disabling that custom Light when electrical power was removed.

---

# Latest runtime fix — NEEDS LIVE TESTING NEXT

A new runtime patch was added:

`LeezGrowLights/Source/Harmony/GrowLightPowerVisualSync.cs`

It patches:

`BlockPoweredLight.updateLightState`

with a late postfix.

It:

* detects LeeZ grow lights
* resolves the `BlockEntityData`
* gets the already-validated electrical state through `PowerStateResolver.IsActive`
* uses **powered AND toggled**
* finds custom Unity `Light` components
* skips vanilla-managed `MainLight` / `Point light` + `LightLOD` branches
* sets custom `light.enabled = active`

This avoids modifying Test6 or the prefab.
